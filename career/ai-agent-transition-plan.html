七、必须避开的坑

  1. 别去啃算法 / 微调 / 训练 / 论文刷分——那是另一个人才池（重学历与科班背景），你的池子是"把模型接进业务并交付结果"。

    掘金《AI Agent 转行真相》：行业呈金字塔分层，绝大多数开发者卡在最底层，不是能力不足，而是学习方向完全偏离企业招聘需求。

  2. 别以为"会用 Cursor / Claude Code"就是 AI 能力——大厂已把 Agent 实战列为要求，"会用工具"只是入场券。
  3. 别只做 Demo——企业区分"用过 Agent Demo"和"把 Agent 跑进过复杂业务"的候选人。所以要有异常处理、评估、部署。
  4. 别丢掉前端优势去换 Python 纯后端——你的差异化恰恰是"懂 AI 又懂复杂交互工程"。

MCP 开发必踩的 5 个坑（提前告知）

  1. stdio transport 下日志绝对不能打 stdout——会污染协议帧导致客户端断连，必须打 stderr。这是新手第一翻车点。
  2. 不要把原始异常/堆栈丢给模型，规范成它能自我纠正的描述（如"股票代码错误，应为 6 位数字"）。
  3. 工具 description 本身就是 prompt——写得越清楚，模型调用越准。
  4. 工具数量别贪多，首版 5-8 个、参数简单，先跑通再优化。
  5. 数据源必须限流 + 缓存，否则会被封。

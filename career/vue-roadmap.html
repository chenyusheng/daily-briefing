0. 先看结论（3 分钟版）#

0.1 你不需要"从零学 Vue"，你需要补三块#

你 10 年前端 + React 主栈，所以：

你要补的 大概要花多久 为什么
模板这层 DSL（v-if/v-for/v-model/slot/指令修饰符） 1 天 React 是 JSX（纯 JS），Vue 模板是受限表达式语法，规则不同但极少
响应式心智模型（ref / reactive / computed / watch 的追踪规则） 1–2 天 这是唯一真正会绊住 React 开发者的地方（自动依赖收集 vs 手动依赖数组）
生态与工程化（Router / Pinia / 组件库 / 构建 / 测试） 2–3 天 概念都能一对一对上 React 生态，属于"查表即用"

结论：认真投入 1 周可以上手写业务，2 周能在项目里独立交付。剩下的深度（编译优化、响应式源码、性能调优）按需补。

0.4 该不该补 Vue：一句判断#

  • 值得补的场景：国内中后台/政企项目 Vue 占比高；Vue 的中文文档、组件库、后台模板生态比 React 更"开箱即用"；你自己要做的报表/后台类应用，Vue + Element Plus 的开发速度优势明显。
  • 不值得的：只为"多一门框架"而学、目标岗位明确只招 React（那就把 React 深度做透）。
  • 顺便说清一个数据：上周（2026-09-05~09-11）npm 下载量 vue 11,281,013 / react 128,119,130。这两个数字不能直接对比——react 是无数包的传递依赖，真实用户基数差距远没有 11 倍。网上"Vue 岗位占前端 38–45%"的说法来自自媒体/博客（非招聘平台官方数据），仅作方向参考，别当论据。

2. React → Vue 心智模型对照（核心章节，建议打印）#

2.1 状态与派生#

关注点 React Vue 3 关键差异
局部状态 useState(0) ref(0) / reactive({}) JS 里要写 count.value；模板里自动解包（{{ count }}）
派生值 useMemo(fn, [deps]) computed(fn) 不用写依赖数组，Vue 自动追踪；依赖不变时不重算
对象状态 useState({}) + 展开新对象 ref({}) 或 reactive({}) reactive 是 Proxy，直接改属性就触发更新；解构 reactive 会丢响应性（用 toRefs）
手动触发更新 setState(n => n+1) 无 改值即更新，没有 setter 概念
批量更新 React 18 自动批处理 默认批处理（微任务队列 flushed 前合并） 下一帧读 DOM 用 await nextTick() 
<script setup lang="ts">
import { ref, computed } from 'vue'
const count = ref(0)
const doubled = computed(() => count.value * 2)   // ≈ useMemo，无 deps
</script>
<template>
  <button @click="count++">{{ count }} / {{ doubled }}</button>
</template>

2.2 副作用与生命周期#

React Vue 说明
useEffect(cb, []) onMounted(cb) 挂载后执行
useEffect(cb, [x]) watch(x, cb) 指定源变化才跑
useEffect(cb) + 内部读值 watchEffect(cb) 自动收集依赖，等价"读过谁就依赖谁"
useLayoutEffect onMounted + await nextTick() / onUpdated —
cleanup return onUnmounted(cb) 或 watch 的 onCleanup 参数 语义一致
依赖数组漏写导致闭包陷阱 不存在 Vue 的 watch 回调拿到的是最新值，不需要 useRef 兜

生命周期钩子映射：onBeforeMount / onMounted / onBeforeUpdate / onUpdated / onBeforeUnmount / onUnmounted / onActivated / onDeactivated / onErrorCaptured。

2.3 模板 vs JSX#

场景 React (JSX) Vue (模板)
条件渲染 {ok && <A/>} / 三元 v-if / v-else-if / v-else；v-show（只切 display）
列表 items.map(i => <Li key={i.id}/>) <li v-for="i in items" :key="i.id">
事件 onClick={fn} @click="fn"；修饰符 @submit.prevent @click.stop @keyup.enter
属性绑定 className={cls} :class="cls"；对象语法 :class="{ active: ok }"
文本插值 {value} {{ value }}（只在模板里，不能用任意 JS 语句）
组件引用 <Child/> 同名，但大小写不敏感：<Child/> / <child/> 都行
子内容 props.children <slot/>（默认）、<template #name>（具名）、作用域插槽
双向绑定 value + onChange v-model="x"；子组件用 defineModel()
DOM 引用 useRef + ref={} useTemplateRef('inputEl')（3.5+）
片段 <></> <template> 多根节点，不需要 Fragment
传透 attributes 手动展开 {...rest} 自动透传到根元素（v-bind="$attrs" 控制）
HTML 注入 dangerouslySetInnerHTML v-html（同样有 XSS 风险，官方明确警告）

模板限制：模板里只能写表达式，不能写语句；能访问的白名单全局有 Math、Date、JSON 等（具体列表见官方「模板语法」）。复杂逻辑一律抽到 computed 或函数里——这反而是 Vue 代码整洁的原因。

6. React 开发者高频踩坑 14 条#

# 坑 正确做法
1 在 <script setup> 里忘了 .value ref 在 JS 里必须 count.value；模板里不用（自动解包）。例外：ref 嵌在对象/数组里不解包
2 解构 reactive 对象后改值不更新 const { a } = toRefs(state)；Pinia 用 storeToRefs(store)
3 解构 Pinia store 后响应式失效 同上，必须 storeToRefs（action 可以直接解构）
4 直接改 props props 只读。要改：emit 通知父组件，或用 defineModel()
5 v-if 和 v-for 写在同一元素上 Vue 3 里 v-if 优先级更高，拿不到 v-for 的变量。正确：外层 <template v-for>，内层 v-if
6 用数组 index 当 key 用业务唯一 id。列表增删排序时 index 会导致状态错位（和 React 同理）
7 以为到处都要手动优化 Vue 更新粒度是组件级+依赖追踪，不需要 memo/useCallback。只有超大列表/大数据对象才用 shallowRef、v-memo 或虚拟滚动
8 用 shallowRef 后改对象属性不更新 shallowRef 只追踪 .value 整体替换；改属性要用 ref 或手动 triggerRef
9 想在模板里写复杂 JS 模板只支持表达式。抽到 computed / 方法里
10 v-model 用于子组件时手写 props+emit Vue 3.4+ 用 defineModel() 一行搞定
11 复制的 React 习惯：useEffect 里做数据请求 用 @tanstack/vue-query 或 onMounted + watch；SSR 场景用 Nuxt useFetch。避免在 watchEffect 里发请求（依赖变化会重复发）
12 以为 scoped CSS 能穿透子组件 scoped 会加 data-v-xxx 属性；要改子组件内部样式用 :deep(...)，改插槽内容用 :slotted(...)
13 手动 document.querySelector 操作 DOM 用 useTemplateRef 拿 ref；DOM 操作放 onMounted 或 await nextTick() 之后
14 现在就把 Vapor Mode 上生产 3.6 仍是 RC（截至 2026-09-16）。生产用 3.5.x；Vapor 只做实验（<script setup vapor> opt-in，可单组件渐进）

7. 面试考点（你在找前端岗，按命中率排）#

必答（中高级岗几乎必问）

  1. 响应式原理：Vue 3 用 Proxy 递归代理 + effect 依赖收集（track/trigger）；Vue 2 用 Object.defineProperty 的缺陷（无法监听数组下标/新增属性、需递归初始化）。
  2. computed vs watch vs watchEffect：computed 有缓存且必须有返回值、是派生值；watch 明确指定源、可拿到新旧值、有 immediate/deep/flush；watchEffect 自动收集依赖、无新旧值。
  3. ref vs reactive：基本类型只能 ref；ref 内部用 reactive 包装对象；reactive 解构丢响应性、reassigned 会失去代理。
  4. 组件更新粒度：Vue 组件级更新 + 依赖驱动（不需要手动 memo），React 是自顶向下 re-render + 手动 memo/useMemo。这是最常被拿来对比的问题，能讲清楚就赢一半。
  5. key 与 diff：Vue 3 用编译期 patchFlag + Block Tree 标记动态节点，运行时 diff 只处理动态部分；key 影响列表复用与状态错位。

加分项（能讲就是亮点）

  1. 编译优化：静态提升（hoistStatic）、补丁标记、Block Tree、v-once/v-memo 的用途。
  2. Vapor Mode（3.6）：跳过虚拟 DOM，编译成直接 DOM 操作，<script setup vapor> opt-in，可与 VDOM 组件混用（vaporInteropPlugin）；包体积和基线运行时显著减小。答"目前还是 RC，生产未采用"反而显得你跟踪得准。
  3. alien-signals 响应式重构（3.6）：基于 push-pull 的细粒度响应式，替换原 @vue/reactivity 实现，3.6 的性能/内存提升主要来自这里。
  4. Pinia vs Vuex：去 mutation（只有 state/getters/actions）、TS 推断友好、setup store 写法、模块化拆分、storeToRefs 原理。
  5. Vue Router 5 变化：把 unplugin-vue-router 并入核心（文件路由）、类型化路由、Data Loaders；对 v4 用户无破坏性变更（官方迁移文档原文）。
  6. SSR 相关：onServerPrefetch、hydration 不匹配（mismatch）的常见原因、useId()（3.5+）、懒水合（Lazy Hydration）。
  7. 性能排查套路：DevTools Performance → 组件重渲染次数 → shallowRef/v-memo/虚拟列表 → 大依赖分包。
